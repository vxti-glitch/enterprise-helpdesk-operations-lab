# Personal lab evidence roadmap

> Do not mark any item `LAB-EXECUTED` until you personally perform it in an authorized, isolated learning environment and redact the resulting capture. This roadmap is intentionally blank evidence planning, not proof that any exercise occurred.

## 1. INC012 — network and DNS triage

Recreate the client-side reasoning in an isolated Windows/network lab. Record the symptom, a gateway or approved IP check, a hostname-resolution check, the approved corrective action, and a before/after validation. Do not capture real network names, public addresses, credentials, or employer systems.

## 2. INC001 or INC002 — guarded AD lab action

Use the sentinel-marked `northstar.example` learning environment only. Start with `Query` and `-WhatIf`, document the exact target and the before/after state, and never publish a password, recovery code, real directory object, or raw audit log.

## 3. One incident or request in a ServiceNow learning instance

Recreate a small representative record in your own Personal Developer Instance. Capture only what you personally configured, use fictional data, show the simulated label, and do not present the image as production or employment experience.

## Manifest requirement

For each approved capture, copy [the blank personal-lab manifest](../templates/personal_lab_manifest.md), complete every field truthfully, save it under `evidence/manifests/`, and place the redacted image under `evidence/screenshots/lab-executed/` with the same file stem. The validator rejects a `LAB-EXECUTED` screenshot reference without that manifest.
